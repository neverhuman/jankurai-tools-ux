# Boundaries

This repository is a single-purpose Node + TypeScript workspace: the
`@jankurai/ux-qa` rendered UX QA package. The machine-readable boundary manifest
is [`agent/boundaries.toml`](../agent/boundaries.toml); this document is its
prose companion.

## Domain

The product surface lives entirely under `packages/ux-qa/src`. There is no Rust
crate, no PostgreSQL database, and no Python AI/data service committed in this
repo, so those stack arms of the family standard are not applicable here.

## Forbidden patterns in domain code

UX QA report generation must stay deterministic and repo-relative. Domain code
under `packages/ux-qa/src` must not:

- embed absolute filesystem paths or machine-specific roots in reports,
- depend on wall-clock time or randomness for report content (artifact digests
  and baselines must be reproducible),
- compare screenshots with pixel or AI/VLM judgment instead of byte/hash
  baselines.

The boundary manifest declares the TypeScript domain path and the forbidden
ambient-effect prefixes it must not import directly.

## Generated zones

Generated output is never hand-edited. The generated zones in this repo are
`packages/ux-qa/dist/` (TypeScript build output) and `target/` (jankurai audit
artifacts), declared in
[`agent/generated-zones.toml`](../agent/generated-zones.toml). They are
regenerated by the build and the audit, not committed.

## Ownership and proof

- [`agent/owner-map.json`](../agent/owner-map.json) assigns an owner to every
  top-level path that exists.
- [`agent/test-map.json`](../agent/test-map.json) routes each owned path to a
  deterministic proof command.
- [`agent/proof-lanes.toml`](../agent/proof-lanes.toml) defines the runnable
  lanes; every lane command executes in this repo alone.

## Reclassification

If a future change adds a Rust, database, or Python surface, update
`agent/boundaries.toml` first to declare the new boundary block, then add the
matching owner, test, and proof entries before landing the code.
